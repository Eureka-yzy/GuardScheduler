# 保安排班系统 · MFC 桌面版

用于 7 名保安的每周轮休排班。每人休息一天，同一排班中每天只有一人休息。系统保留原控制台版的账户、排班记录、轮休规则和查询逻辑。

## 运行与编译

解压到 Windows 中有读写权限的本地目录，然后运行 `bin\x64\Release\GuardScheduler.exe`。同目录已附带 `guard_info.txt`。首次打开时，填写账号和密码，点击 **注册**。注册成功后再次输入密码，点击 **登录**。如果已迁移旧账户，可直接登录。

如需从源码编译，请在 Visual Studio Installer 中安装 **Visual Studio 2022** 的 **使用 C++ 的桌面开发** 工作负载、**MSVC v143**、**Windows 10 或 11 SDK** 和 **适用于最新 v143 生成工具的 C++ MFC（x86 和 x64）**。工程使用 Unicode、C++17 和静态 MFC。

1. 打开 `GuardScheduler.sln`。
2. 在工具栏选择 **Release** 和 **x64**，然后选择 **生成 → 生成解决方案**。
3. 运行 `bin\x64\Release\GuardScheduler.exe`。如需调试，选择 **Debug | x64**。

生成时，工程会把根目录的初始 `guard_info.txt` 复制到尚无该文件的输出目录。需要更新名单时，请编辑实际运行的 exe 旁边那份文件。

也可以在 Visual Studio 2022 Developer Command Prompt 中编译。

```bat
msbuild GuardScheduler.sln /m /p:Configuration=Release /p:Platform=x64
```

安装组件可参照 [Microsoft 的 Visual Studio 2022 组件列表](https://learn.microsoft.com/visualstudio/install/workload-component-id-vs-community?view=vs-2022)。

## 保安资料

程序启动时读取与 `GuardScheduler.exe` 同目录的 `guard_info.txt`。文件使用 UTF-8，每行一名保安，共七行。字段依次为姓名、编号、电话、岗位或地址，以半角竖线 `|` 分隔。编号须唯一，同名人员可用编号区分。

```text
赵|BA01|13811111111|文苑路九号
```

修改文件后重新启动程序，排班、当天值班和保安档案会使用更新的资料。人员按编号排序，调整文件行顺序不影响历史排班的对应关系。已有排班时请保留原编号，因为历史记录按编号顺序保存轮休和特殊情况。

## 操作

| 操作 | 步骤和规则 |
| --- | --- |
| 手动新增 | 填写周次（1–999），为每位保安选择休息日，按需选择特殊情况和填写备注，点击保存并确认。重复的休息日会提示重新选择。 |
| 自动排班 | 为每位保安勾选可接受的休息日并生成方案。列表显示全部可行方案。可以输入方案编号定位，选中后点击 **采用方案**，填写周次、可选的特殊情况和备注并保存。无解时，按提示调整勾选后重试。 |
| 查看排班 | 在主表中选择记录，或输入记录编号点击 **查找**。主表显示该排班的原因类别，详情列出每种原因对应的保安以及轮休、备注和创建修改信息。 |
| 修改休息日 | 选中记录后点击 **修改休息日**。选择保安后，可以更改或清除该保安的特殊情况，也可以更改休息日。若新日期已有他人休息，系统预览并交换两人的休息日。保存时会记录修改人和时间，修改说明会追加到原备注。 |
| 删除记录 | **删除选中** 需要一次确认。**删除全部** 需要两次确认。 |
| 当天值班 | 系统显示本机时间、星期和 ISO 周次。只有一条记录时直接采用该记录。有多条时选择参考周次，系统取该周编号最大的一条，列出当天值班保安的信息和休息人员的已登记原因。 |
| 保安档案 | 在表中选择人员，或按完整姓名查找。同名时可按编号区分。系统查询本周及前三周，每周取编号最大的一条，显示工作日、休息日、已登记的休息原因以及缺失的周次。 |

特殊情况默认是 **无特殊情况**。如有多种原因，主表和详情按 **看病 > 办证 > 旅游** 的顺序展示。这个顺序用于展示。手动校验和自动生成方案继续使用原来的休息日约束。交换休息日后，原因仍跟随原登记的保安。

排班按周次升序排列，同周按原记录顺序排列。新增和删除后会重新编号，因此编号可能变化。周次沿用原版的数字字段，排班数据中没有年份。最近四周遇到周次小于 1 时会跳过该周。

## 迁移旧数据

1. 退出控制台版和桌面版，备份控制台版目录中的 `users.txt` 和 `schedule.txt`。
2. 将这两个 UTF-8 文件复制到 `GuardScheduler.exe` 所在目录，并保留同目录的 `guard_info.txt`。若该目录已有同名文件，先备份其中的数据，再决定是否替换。
3. 启动桌面版，用原有账号登录，并在主表核对排班。首次注册或保存排班时，程序会在该目录创建所需的数据文件。

`users.txt` 沿用每行一个账号及明文密码的格式。请按账户资料保管该文件。`schedule.txt` 沿用原来的竖线分隔格式。旧版记录的原因默认是 **无特殊情况**。新版仅在登记原因的记录尾部写入扩展字段。请使用新版编辑含原因的排班，旧程序保存时会丢弃该字段。若账号或备注含有竖线，MFC 版会转义该记录中的特殊字符并追加格式标记。请退出程序后再替换或编辑数据文件。

## 源码与核对方法

- `src/App.cpp` 和 `src/Dialogs.cpp` 负责应用入口、主界面和各业务对话框。中文界面资源位于 `src/GuardScheduler.rc`。
- `src/Scheduling.cpp` 保留原位掩码 DFS 的遍历与方案顺序，以及增广路径求二分图最大匹配的算法。桌面版将可选日限制为周一到周日，并修正无解诊断的数组下标和提示语。
- `src/Repository.cpp` 负责读取七名保安资料和读写 UTF-8 账号、排班文件。保存时在同目录生成临时文件，写完后替换原文件。
- `legacy/main.cpp` 是原控制台源码。它独立保留在归档中。
- `tests/CoreTests.cpp` 覆盖保安文件读取和编号排序、排班枚举、无解诊断、跨年周次、账号验证、旧数据读取、特殊情况保存和清除、交换休息日及保存删除。以下命令在 Visual Studio 2022 Developer Command Prompt 中运行，只使用临时数据。

```bat
cl /nologo /std:c++17 /EHsc /utf-8 /DNOMINMAX tests\CoreTests.cpp src\Scheduling.cpp src\Repository.cpp /Fe:CoreTests.exe
CoreTests.exe
```

新版在 Windows 11 上使用 MSVC v143 命令行编译，并通过核心测试和界面流程核对。此次界面核对覆盖名单缺失提示、从名单加载姓名、手动和自动排班、当天值班、保安档案，以及在修改姓名和名单行顺序后重启读取旧排班和原因。核心测试包含 5,040 个可行方案的枚举检查。
